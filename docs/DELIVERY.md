# 交付说明与差异记录

日期：2026-11-03；最近同步：2026-11-12。对应方案基线 `docs/IMPLEMENTATION_PLAN.md`。本文记录实际落地内容、与方案的差异、验证结果和遗留项，避免把“计划”误读成“已完成”。当前代码结构与模块职责见 [ARCHITECTURE.md](ARCHITECTURE.md)，技术栈升级评估见 [UPGRADE_ASSESSMENT.md](UPGRADE_ASSESSMENT.md)。

## 1. 交付范围

已实现一条可运行的纵向闭环：注册登录 → 建行程 → 建/导地点 → 排事项 → 看时间线与冲突 → 手工或真实路线 → 单日优化预览并应用 → 版本历史与恢复 → 攻略导出（MD/DOCX）→ 分享只读页。

未实现：找回密码、Redis/RQ、Alembic 迁移、Docker Compose/Nginx、GIS 栅格与矢量瓦片、地形与三维、外部图层服务、PWA 离线、多日优化、OR-Tools、附件与图片、原生 App 与 Electron。邮箱验证码与可选 SMTP 已实现（未配 SMTP 时验证码写日志）；分享页当前只展示攻略快照，不包含地图图层。

判定标准遵循 `AGENTS.md`：不把"页面能打开""接口返回 200"当作完成；每个能力在 `/api/v1/providers/capabilities` 中标注 configured/verified，未实测项不宣称可用。

## 2. 架构落地

```text
浏览器 (React 18.3.1 + Vite 6 + antd 5 + MapLibre 5；升级评估见 docs/UPGRADE_ASSESSMENT.md)
   │  Cookie 会话 + X-CSRF-Token
   ▼
FastAPI (同步端点，线程池执行) ── SQLAlchemy 2 ── PostgreSQL 17 / PostGIS 3
   │                                   └─ trip_revisions 全量快照
   ├─ 供应商适配器（高德 / 天地图）── httpx，超时 3s/10s，重试一次
   └─ 任务执行器（线程池 + jobs 表状态机）
```

模块划分与方案一致：`auth / trips / places / stops / routes / optimization / exports / shares / jobs / providers`，API 与任务处理器共用一个 Python 代码库，不引入第二套后端。

几何在数据库是 `geometry(POINT|LINESTRING, 4326)`，在接口与快照是 GeoJSON（`[经度, 纬度]`），转换只发生在 `services/geostore.py`。这样 PostGIS 可做空间索引与后续空间查询，业务层不需要理解 WKB。

版本机制：所有内容写接口要求 `If-Match: "<revision>"`，事务内 `SELECT ... FOR UPDATE` 锁行程行、校验 revision、flush 内容、写全量快照、revision+1。分享与导出都从 `trip_revisions` 取同一条快照，因此"当前行程已改、导出还是旧内容"不会发生。

## 3. 关键设计决策

| 决策 | 理由 | 代价 |
| --- | --- | --- |
| 口令用 `hashlib.scrypt`（N=2^14, r=8, p=1） | 方案写的算法名在文档中是占位词，本机无 Argon2 依赖；scrypt 同为内存硬散列且在 stdlib | 与 Argon2id 的行业推荐不同，后续可平滑替换（`security.py` 单点） |
| CSRF 由会话令牌 HMAC 派生 | 刷新页面后服务端可重算同一值，无需存明文，也不把令牌放 localStorage | 令牌泄露即 CSRF 失效，与 Cookie 同源风险一致 |
| 任务用线程池 + 数据库状态机 | 本机无 Redis；契约要求的状态、幂等、取消、重试语义必须保留 | 单进程有效；多副本需换 RQ/Celery，`services/jobs.py::submit` 是唯一替换点 |
| 无路网数据时使用"直线 × 绕行系数"估算矩阵 | 让优化在无 Key 时仍可演示与测试，且结果强制标注 `matrix_source=estimate` 与 assumptions | 估算值不能用于承诺真实行程时间，UI 与导出均带警示 |
| 供应商记录默认不落库，只保存用户复制的最小字段 | 没有书面授权证据，`persist=unknown` 不能当作 allowed；但"自建地点"是允许的 | 搜索结果保存后不再关联 provider_id，无法回查详情；需在取得授权后改策略 |
| 分享快照只存业务投影（快照 JSON） | 历史、导出、分享、离线必须来自同一份允许保存的数据 | 含几何副本，体积随版本增长 |
| 优化仅支持单日 | 多日分配需要真实矩阵、节点上限和更复杂的约束建模，半成品会误导 | `scope=trip` 明确拒绝，不静默降级 |

## 5. 安全与数据权利边界

### 5.1 数据源 Key 的存放

Key 通过设置页写入 `app_settings` 表，使用 `SESSION_SECRET` 派生的 Fernet 密钥加密；接口只返回 `masked`（前 4 位 + 后 4 位），明文不下发。保存后重建适配器缓存，底图与查询能力立即变化，无需重启。只有 `role=admin` 的用户可以写入；第一个注册者自动成为管理员，`scripts/init_db.py` 在旧库上会补齐该列并提升最早的用户。天地图浏览器瓦片 Key 必然出现在前端瓦片 URL 中，这是浏览器底图的固有约束，只能靠控制台域名白名单限制。


- 会话令牌 32 字节随机，库中只存 SHA-256；Cookie HttpOnly、SameSite=Lax、生产可加 Secure；空闲 7 天、最长 14 天。
- 登录限流 10 次/15 分钟（IP+邮箱），注册 5 次/小时，分享密码 5 次/15 分钟；限流为进程内，多副本需改 Redis。
- 越权统一返回 404，不区分"不存在"和"无权访问"；文件下载与分享访问都重新校验归属与有效期。
- 供应商 Key 只在服务端环境变量中读取；`/config/public` 只返回布尔可用性和受域名限制的浏览器瓦片 Key。
- 日志不记录请求体与 Key；错误响应不含堆栈与上游原始报文。
- 分享页明确告知：已下载到设备的副本无法被服务端撤回。

实测中发现并修复的缺陷（均已回归）：

1. `trip_stops` 曾按 `day_id`（UUID）排序，导致地图编号与日期错位；改为关联 `trip_days` 按日期排序。

5. 移动端顶栏溢出、图标被误隐藏、面板顺序不合理；已用媒体查询修正。

## 8. 对原方案的几点意见

1. **范围与节奏不匹配**：P0–P5 加 Electron，覆盖账号体系、双供应商、GIS 栅格、地形、优化、离线、分享、导出，按单人投入是数月量级。建议把首版收窄为"可保存的行程 + 时间线 + 导出 + 分享"，GIS 与三维放到第二阶段；方案已经写了"先纵向"，但模块清单仍是全景，实施时容易同时铺开。
2. **用途矩阵的可操作性不足**：把 `persist` 默认设为 unknown 在合规上正确，但会直接切断"搜索→保存"这一核心路径。建议改成字段级策略：名称、坐标、类别这类事实性最小字段允许保存并强制标注来源，介绍、图片、评分等受限字段禁止；否则产品只能退化为纯手工录入。
3. **优化指标与配额冲突**：方案要求"单日 5 秒、多日 10 秒求解"，但同时把供应商 QPS 限制为 1、单任务 400 段。真实矩阵的获取时间远大于求解时间，应该把预算写成"矩阵请求数优先，求解时间其次"，并明确矩阵可以复用与缓存的条件。
4. **并发模型成本被低估**：800ms 防抖自动保存 + 全量 revision + If-Match，意味着同一用户多标签页编辑会频繁 409。建议按实体粒度做版本（或至少把 notes 之类长文本单独存放），否则冲突提示会成为日常干扰。
5. **时间语义需要收紧**：方案允许任意 IANA 时区与 DST 歧义处理，但目标用户是中国大陆个人出行。建议首版固定 `Asia/Shanghai`，把时区做成只读字段，减少一类难以测试的缺陷。
6. **历史快照体积**：30 天 × 30 事项的快照约几十 KB，200 个版本约 10–20MB/行程。单机可以接受，但应在写入时压缩（JSONB + zstd 或 gzip 列），否则备份与恢复时间会被放大。
7. **地图表现依赖外部配置**：空白底板下 12 个点会挤成一团。现已接入天地图瓦片并按地点范围自动 fit，但出图仍受制于控制台域名白名单，代码替代不了这项配置。建议设置页把当前访问地址（`location.origin`）直接显示出来，方便对照白名单填写，已列入 P2。

8. **验收项与外部依赖耦合**：P0 出口要求"每项外部能力有真实成功/失败结论"，在用户不提供 Key 时无法达成。建议把 P0 拆成"离线可完成"（版本、锁文件、坐标、最小地图、固定数据）与"需 Key"两组，避免整个阶段被单个外部条件卡住。
