# 验收、测试与阶段完成标准

本清单对应 IMPLEMENTATION_PLAN 和 API_CONTRACT。数值是项目目标，不是已运行测试报告。**当前仓库不是“只有方案文档”**：已实现一条可运行纵向闭环，但本清单中的多数条目仍未逐项验收。实际结构见 [ARCHITECTURE.md](ARCHITECTURE.md)，实现差异与验证记录见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 10 节。历史记录（2026-11-04）：`pytest tests -q` 为 29 passed。2026-11-12 工具链与 UI 栈升级后复跑：纯逻辑测试 16 passed；全量 `pytest tests -q` 为 16 passed / 16 skipped（未设置 `TEST_DATABASE_URL`）；前端 `pnpm typecheck`、`pnpm build`、`pnpm peers check` 均通过。未勾选不代表已通过。

## 1. 检查环境与固定数据

- 本地服务以Linux容器运行；开发设备可为Windows。CI和部署使用相同的GDAL/PostGIS主要版本。
- 固定自建测试行程：北京2日、杭州3日、成都山地行程；自建地点和合成交通矩阵，不复制受限供应商响应作为fixture。
- 几何数据：WGS84点线面、CGCS2000/投影坐标样例、含中文属性Shapefile、GPX/KML、GeoPackage多图层、RGB GeoTIFF、单波段DEM、nodata边缘样例。
- 交通矩阵包含非对称、不可达、时间窗等待、硬预约、必去冲突及可选舍弃。地图转换包含北京/上海/成都/广州/境外对照。
- 端到端桌面视口1440×900；手机390×844；补测360px窄屏。真机至少Android Chrome和iPhone Safari各一台；没有真机时标记待验证，不能用模拟视口冒充。
- 联网测试默认关闭，显式启用项目专用测试Key时才执行小批量真实查询，记录日期、用量和数据用途，不录制原始敏感响应。

## 3. P1：账号、行程、编辑与历史

### 账号和归属

- [ ] 注册→收验证邮件→验证→登录→退出；错误密码/过期令牌/重复令牌/找回密码均符合契约。
- [ ] 生产未配置SMTP不能绕过邮箱验证；开发邮件接收器与生产配置隔离。
- [ ] A不能通过修改trip、place、stop、asset、dataset、job、share ID访问B的数据，所有入口都验证。
- [ ] CSRF、跨Origin请求、登录限流和密码散列工作；退出及密码修改撤销相应会话。
- [ ] 登录令牌不在localStorage、URL、日志、数据库明文中。

### 行程编辑

- [ ] 创建3日行程，添加自有景点、餐饮、酒店和交通事项；日期/金额/坐标/时区错误有清晰反馈。
- [ ] 候选池→某天→另一日→候选池可逆；排序不重不漏，锁定项不能被普通重排突破。
- [ ] 手机可用按钮完成排序/跨天操作，所有核心功能不依赖悬停/右键/拖拽。
- [ ] 标注点线面及属性保存，刷新后位置和属性不丢；地图选中与列表联动。
- [ ] 日期缩短将越界事项放回候选池，预约清除规则和警告明确；未越界事项日期不平移。
- [ ] 800ms自动保存合并连续输入；失败可重试，切页不会默默丢弃输入。
- [ ] 两个浏览器同时编辑同一revision，后提交者409；UI保留草稿并提供加载当前版本的路径。
- [ ] 每次成功内容事务revision递增且有快照；事务失败不产生半个版本。
- [ ] 查看历史只读；恢复写成新版本，关联资产有效并重新检查用途。
- [ ] 删除行程立即使分享/任务结果/下载不可用，无引用资产按保留期清理。

## 4. P2：双供应商与交通

- [ ] 同一关键词可分别搜索天地图、高德；双源分组，不自动混并ID。
- [ ] 输入提示去抖，旧请求取消；旧结果晚到不覆盖新搜索。
- [ ] 空结果、超额、鉴权失败、HTTP200业务失败、超时分别呈现；自动/显式来源切换符合契约。
- [ ] 路线、POI和属性显示来源及查询时间；未知门票、开放时间、图片不由测试占位内容冒充事实。
- [ ] 景区中心与导航入口不同的样例使用入口规划路线，展示位置保持景点位置；未设入口有核实提示。
- [ ] 驾车/步行按真实路网返回；不可达不画导航直线，不把服务失败解释成空结果。
- [ ] 公交带出发时间和城市；改变上一项时间后下游查询失效重算。
- [ ] 没有完整公交时刻能力时显示供应商限制，手工交通事项仍可用。
- [ ] 地点/顺序/日期/交通模式改变使路线stale，不再以旧耗时显示确定到达时间。
- [ ] Route/POI受限字段不会出现在DB、Redis、客户端持久缓存、历史、导出或分享。
- [ ] 不允许跨地图展示的供应商内容不叠加；不允许转换的坐标不假装标准GeoJSON。
- [ ] no-store和PWA NetworkOnly路径覆盖所有受限查询；禁用Query持久化和无意自动重取。
- [ ] 权限/授权到期后历史、分享、下载重新检查；已有文件不可撤销的边界有准确提示。

## 5. P3：行程优化与任务可靠性

| 场景 | 预期 |
| --- | --- |
| 简单可重排路线 | 输出可行顺序，预览前不更改trip |
| 方向相关矩阵 | A→B与B→A分别使用，结果不假设对称 |
| 开门前到达 | 安排等待，开始不早于窗口 |
| 多段开放/跨日 | 选合法区间，不安排在关门时段 |
| 固定预约 | 满足固定开始时间，冲突时清晰诊断 |
| 必去项不可能全部满足 | 返回不可行，不静默丢弃必去 |
| 可选项过多 | 按优先级舍弃，返回名单和原因 |
| 锁定日期/相对顺序 | 不跨锁定日期，不打乱被锁事项相对顺序 |
| 多天不同酒店 | 使用各日起终点和可用时段，同一景点不重复分配 |
| 不可达或矩阵缺项 | 无伪可行边，超过预算明确失败 |
| 缺起终点/超节点限制 | 在启动昂贵请求前返回可解释错误 |
| 到达求解时限但有可行解 | succeeded/time_limit，明确结果不是全局最优证明 |
| 优化期间用户已编辑 | 查看建议可行；应用409，原行程不被覆盖 |
| 原始数据用途受限 | 不将矩阵/路线写入RQ或快照，不能变相导出 |
| 静态矩阵与复核路段不同 | 标注交通估算基准，违反硬约束时不应用，不宣称未来路况已验证 |

- [ ] 首次入队DB成功但Redis失败，派发器恢复后不丢任务；重复投递只产生一次成果。
- [ ] 相同幂等键相同请求复用任务，不同请求409；失败重试创建新任务并检查输入。
- [ ] Worker崩溃、超时、取消、重启及中间文件清理均有可观察状态，无永久running任务。
- [ ] 文件成果采用临时写入+原子发布，未完成文件不可下载。
- [ ] 计费请求预算包含重试；QPS和配额保护在并发任务间共享生效。

## 6. P4：GIS、轻三维、攻略与分享

### GIS

- [ ] 每种列出的文件格式至少一个正常样例；多图层GeoPackage可选图层，中文属性不乱码。
- [ ] 缺CRS进入确认状态；未知/错误CRS不改标签冒充转换。
- [ ] 路径穿越ZIP、异常压缩比、大图像、超文件/要素/顶点上限被拒绝；已上传文件不公开可枚举。
- [ ] 损坏/非法几何生成报告，不悄悄修复后改变结果。
- [ ] 小矢量按范围GeoJSON，大矢量MVT；手机不下载10万要素原始文件。
- [ ] RGB/单波段GeoTIFF正确出图，nodata透明，图层透明度和顺序可调整。
- [ ] DEM地形起伏正确，nodata和边界无明显尖峰，范围外回落平面；最多一个terrain。
- [ ] 2D/倾斜切换保持图层、标注、选中项和行程；手机默认为2D。
- [ ] XYZ/WMTS/WMS/MVT受支持组合通过；不支持的投影/矩阵明确说明。
- [ ] 外部URL拒绝内网/环回/元数据/重定向/DNS重绑定，不关闭CORS或webSecurity绕过。
- [ ] WebGL不可用有行程与攻略入口，不白屏。

### 攻略与分享

- [ ] 同一revision的MD、ZIP和DOCX地点顺序、时间、费用、备注一致，来源/更新时间正确。
- [ ] ZIP中图片相对路径可离线打开；解压到中文目录仍可用。
- [ ] DOCX在Word/WPS人工打开检查至少一份长文：中文、链接、图片、重复表头、分页和长备注不溢出。
- [ ] 存在真实地图和自有示意图两种路径；缺地图许可不截图绕过。
- [ ] 非路网示意连线明确标注，未授权字段不通过图像/附件再次输出。
- [ ] 分享固定版本、到期、密码、撤销、允许复制均生效；当前修改不悄悄改已分享内容。
- [ ] 分享不能访问其他行程资产或当前私有图层，不暴露邮箱/凭据/内部URL。
- [ ] 下载导出检查成果到期、行程软删和当前用途；无法猜ID下载他人文件。
- [ ] 显式离线下载后断网可打开攻略，显示版本/时间；搜索/改路线提示联网，离线只读。
- [ ] PWA退出/切换账号清理缓存；Android/iOS安装与离线流程分别记录真机结果。

## 7. 性能、发布与运行验收

性能目标在4vCPU/8GB内存的单机容器部署参考环境、本地固定数据、≤20个活跃用户条件下测量；报告实际设备和数据规模。真实供应商延时不计入本地接口耗时目标，但单独报告。

- 普通行程读写与权限接口p95≤500ms；大文件/复杂查询通过后台任务，不阻塞普通API。
- 390px手机工作台无横向溢出，核心点击有即时反馈；地图5000简单点位聚合后可缩放拖动，实际帧率/内存记录设备，不虚构统一GPU指标。
- 初始Web包对地图/GIS按路由拆分，首屏不加载Electron依赖、完整GDAL或全部GIS文件；网络失败能打开已缓存攻略。
- 自建30事项攻略MD/DOCX导出目标≤30秒，不含上游地图请求，超时有明确信息。
- [ ] 类型检查、lint、领域单测、API集成、关键E2E通过；OpenAPI生成类型与仓库一致。
- [ ] 迁移在空库和上一阶段库均可运行；失败不会破坏可恢复备份。
- [ ] HTTPS、同域、Cookie、代理上传限制、私有卷、容器资源限制正确。
- [ ] 前端包/接口/日志无服务端Key，生产无测试登录旁路或模拟数据冒充真实。
- [ ] 数据库和文件备份可恢复，完成一次新环境恢复演练并记录实际RPO/RTO。
- [ ] 运行手册包含配置、启动、迁移、SMTP、Key类型、数据源策略、备份、恢复、升级和清理。
